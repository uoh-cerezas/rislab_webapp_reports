## Desarrollo
Se utiliza esto para no construir la imagen de docker cada vez que se haga un cambio
1. Construir venv python
```bash
python3 -m venv venv
```

2. Activar venv (linux)
```bash
source venv/bin/activate
```
- Para comprobar si esta activado el ambiente, tiene que salir una ruta que este dentro del proyecto, sino activar ambiente, si esto no funciona, hacer todos los pasos de nuevo
```bash
which pip
```
3. Instalar dependencias
```bash
pip install --no-cache-dir dash dash-bootstrap-components pymongo flask numpy plotly pandas dash-iconify flask-cors
```
4. Correr app (con flask)
```bash
python3 app.py
```
## Dashboard Container-Docker

1. Construir la imagen del contenedor:

```bash
docker build -t dashboard_image .
```

2. Leventar el contenedor:

Asegúrate de que tiene permisos de ejecución:

```bash
chmod +x start-app.sh
```

Ejecuta el script de levanta el contenedor:

```bash
./start-app.sh
```

3. Entrar al app web de forma local:

```
http://localhost:8050
```

## Existing climate reports (read-only)

The reports page reads PDFs already generated by the `climate-reporting`
container. It scans `/data/runs/<kind>/<report-date>/manifest.json` and exposes
only entries whose manifest is `complete` and whose PDF has
`generated: true`. The website does not run the reporting pipeline, does not
create reports and does not write to MongoDB.

On the server, mount the persistent reporting directory read-only:

```bash
docker run -d --name dashboard_app_reports_test \
  --network FIC-app-network -p 8051:8050 \
  --env-file /home/uoh/tmp/dashboard-test/dashboard.env \
  -e CLIMATE_REPORTING_DATA_ROOT=/data \
  -v /home/uoh/cerezas_web_server/data/climate-reporting:/data:ro \
  --restart unless-stopped dashboard_image:reports-readonly-test
```

Keep the production `dashboard_app` and `climate-reporting` containers running
while testing. The `start-app.sh` script expects an external runtime env file
(`DASHBOARD_ENV_FILE`) and mounts the same data directory read-only; credentials
must never be committed to this repository.

The report catalog is available at `/reportes_chillhours` after login. Users
only see sites authorized in their existing session whose identifiers start
with `fic2-`; `fic1-` entries are intentionally excluded. They can filter
daily, weekly and monthly reports. Downloads use a signed token and a path
confined to the `/data` mount.

## Administrator-only NOC integration

The `/noc` route is an authenticated gateway to the independent `ttn_noc`
service. It reuses this application's existing session and administrator role
(`role == 0`); unauthenticated users are redirected to `/login`, and
authenticated non-administrators receive `403 Forbidden`. The NOC container
does not implement a second login and must not be exposed directly to the
internet.

Set `NOC_UPSTREAM_URL` in the dashboard container. Use
`http://ttn-noc:8060` when both containers share a Docker network, or
`http://host.docker.internal:8060` for a local Docker Desktop test. The NOC
container must use `NOC_BASE_PATH=/noc` so its browser assets and API requests
remain below the website prefix.

Administrator protection is enabled by default. For an isolated authenticated
test account without administrator privileges, set `NOC_ADMIN_ONLY=false` in
the test container only. Never use this override in production.

The `start-app.sh` helper forwards `NOC_UPSTREAM_URL` automatically:

```bash
NOC_UPSTREAM_URL=http://host.docker.internal:8060 \
DASHBOARD_ENV_FILE=/path/to/dashboard.env \
APP_NAME=dashboard_app_noc_test PORT=8051 \
./start-app.sh
```

The website proxy is read-only: it forwards only GET requests to the NOC and
does not write to TTN or MongoDB.

## Administrator configuration dashboard

The administrator menu includes `Configuración de reportería`, which opens the
standalone `climate_admin_dashboard` in a new tab. The website keeps the
authentication boundary (`role == 0`) and proxies the dashboard at
`/admin/config/`; the dashboard itself does not implement a second login.

For local integration, start both containers on the same Docker network and
set `ADMIN_CONFIG_UPSTREAM_URL=http://climate-admin-dashboard:8070` when
running `start-app.sh`. The dashboard's local compose override creates the
network `fic-local-network` by default. Configuration files are mounted into
the dashboard separately; no database or report-generation process is
started by this integration.

Each row provides inline PDF visualization and individual download. The
`Descargar todos` action sends the currently filtered report tokens to the
server and returns a ZIP archive. The archive is created in memory and is not
stored in the reporting directory.

Administrators (`role == 0`) can inspect all generated reports. For a temporary
test account with no assigned fields, set
`CLIMATE_REPORTS_ALLOW_UNASSIGNED=true` only in the test container environment;
leave it unset or `false` in production.

Run catalog tests with Python 3.10+:

```bash
python -m unittest discover -s tests -v
```

# ID

Here is a list of all the `id`s used in your application, along with their purpose and how they are used in callbacks:

---

### **1. `open`**

- **Type:** Button
- **Location:** `requirements()` function in admin_view.py
- **Purpose:** Opens the modal popup.
- **Callback:**
  - **File:** modals_callbacks.py
  - **Callback Function:** `toggle_modal`
  - **Description:** When this button is clicked, it toggles the `is_open` state of the modal (`modal`).

---

### **2. `close`**
